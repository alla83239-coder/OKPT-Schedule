# Архитектура системы

## Принципы

1. Справочники и плановые назначения отделены от конкретных календарных занятий.
2. Источники импортируются в staging-слой; до подтверждения человеком они не становятся производственными данными.
3. Для каждого значения сохраняются источник, страница/лист, исходный фрагмент и статус проверки.
4. Жёсткие ограничения не нарушаются алгоритмом. При невозможности составить расписание система показывает конфликтующие требования.
5. Рабочее время преподавателя, педагогическая нагрузка и фактические аудиторные часы учитываются отдельно.

## Предлагаемые компоненты

- Frontend: Vite, JavaScript на первом этапе; затем можно перейти на TypeScript/React при необходимости.
- Backend: API-сервис (планируется).
- Database: PostgreSQL в целевом развертывании; локально — тестовая БД/seed.
- Scheduler: отдельный сервис оптимизации на Google OR-Tools CP-SAT.
- Import pipeline: PDF/DOCX → извлечённые данные → проверка/сопоставление → подтверждённый реестр.
- Exports: XLSX/PDF после стабилизации модели.

## Основные сущности

- department, specialty, student_group
- teacher, teacher_qualification, teacher_availability
- discipline, curriculum, curriculum_item
- academic_calendar, calendar_period

## Ограничения расписания

### Жёсткие

- один преподаватель не может вести две сессии одновременно;
- одна группа/подгруппа не может посещать две сессии одновременно;
- одна аудитория не может быть занята двумя сессиями одновременно;
- вместимость и тип аудитории должны соответствовать занятию;
- соблюдаются доступность преподавателя, календарь группы и учебный план;
- для группы не более 4 пар в день и не более 36 академических часов в неделю (настройки должны быть явными и проверяемыми);
- сессии практики/аттестации не планируются в обычные периоды теоретического обучения, если календарь группы задаёт иной режим.

### Мягкие

- уменьшение окон преподавателей;
- равномерное распределение недельной нагрузки;
- предпочтения по дням/времени;
- избегание чрезмерного количества повторов одной дисциплины за день;
- рациональное использование специализированных помещений.

## Подгруппы

Правило деления хранится на уровне дисциплины и группы: число подгрупп, состав, режим (одновременно/последовательно), преподаватель и объём часов. Для последовательного режима каждая подгруппа получает свои занятия в отдельные временные интервалы; группа не считается занятой в период, когда занимается другая подгруппа, если студенты не пересекаются.

## Замены

Замена создаётся как отдельная запись, не изменяющая исходное назначение преподавателя. Перед применением проверяются предметная квалификация, доступность, пересечения, кабинет и допустимая нагрузка. Применение требует подтверждения и фиксируется в аудите.

## Импорт и контроль качества

Ни один OCR-результат не становится справочником автоматически. Для каждого поля нужен статус: `extracted`, `needs_review`, `approved`, `rejected`. Особо важна геометрическая реконструкция календарных таблиц и расписания, поскольку текстовый слой может терять связи между строками и столбцами.
